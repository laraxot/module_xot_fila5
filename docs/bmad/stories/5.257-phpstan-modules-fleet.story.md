# 5.257 — PHPStan `analyse Modules`: campagna a zero errori con swarm

> **SUMMARY**: il 28/09 il gate era a zero ma solo perche' i 739 file con marker di merge erano
> stati ripristinati da HEAD. Il 29/09 i marker sono ricomparsi in 7-8 file diversi nell'arco di
> sei minuti, poi sono spariti da soli: **il worktree e' sotto scrittura di altri agenti e il
> gate non e' un fatto stabile**. Questa story tratta il gate come un problema di *concorrenza*,
> non come un numero da raggiungere una volta.

## Perche' (la lezione, non il numero)

Il claim "0 errori" del 28/09 era vero **solo per quell'istante**. La verifica di oggi:

| Ora | File con marker | Moduli coinvolti |
|---|---|---|
| 14:24 | 8 | Job (5 List page), Lang (2 `txt.php`), IndennitaResponsabilita (1) |
| 14:30 | 7 (**insieme completamente diverso**) | Lang (2), Media (3 List page), Notify (2 List page) |
| 14:33 | **0** | — |

I 5 file `Job` non avevano piu marker senza che nessuno li avesse toccati: un altro agente li ha
riparati. E mentre guardavo, sono comparsi altri 7 su moduli diversi.

**Regola che ne deriva**: non si può trattare un insieme di file come stabile. Per ogni file,
**ricontrollare il marker immediatamente prima di editare**, e verificare lock + mtime. Un
`grep` fatto 10 minuti prima è un dato scaduto.

## Vincoli

- `phpstan.neon` e' **sacro**: mai `-c`, mai `--level`, mai baseline. `level: max`, `ignoreErrors` vuoto.
  "Gli errori vanno corretti, non ignorati" e' la ragione per cui la baseline e' commentata.
- Mai `git checkout --` / `git restore` / `git reset` (forward-only). Per ripristinare un file:
  `git show HEAD:<path> > <path>`.
- Mai `migrate:fresh` / `--force` / `RefreshDatabase`. Host `10.100.200.15` = nessun test.
- `laravel/.env` e' ASSENTE in questo ambiente: **Pest non e' eseguibile**, il gate Pest resta uno skip
  documentato, non un verde.
- `Modules/<Mod>/` e' anche un repo git separato: `git status` va eseguito **dentro** il modulo.
- Clone annidato `Modules/Activity/Activity/` = fuori scope (350 PHP duplicati, committati).
- Lock: `bashscripts/lock/lock.sh <path-relativo-root> <task> <agent>`, rilascio con
  `unlock.sh <path SENZA .lock>`. Un subagent morto **non** rilascia i lock: usare il campo
  `Agent:` dentro il lock per distinguerli.

## Strategia: swarm su moduli disgiunti

Gli errori si distribuiscono per modulo, e i moduli sono repo indipendenti: il parallelismo e' naturale
e le collisioni improbabili. Un solo errore alla volta sul modulo principale sarebbe il collo di bottiglia.

1. Analisi completa con `--error-format=json` (machine-readable: si raggruppa per modulo e per tipo
   senza parsing fragile del testo).
2. Clustering degli errori per modulo, ordinamento **random** come richiesto (i moduli con piu' errori
   non devono andare per primi: li si affronta quando gli altri hanno gia' liberato i lock).
3. Un subagent per gruppo di moduli, file disgiunti, lock per file.
4. Verifica finale: `parallel-lint` (parse) -> `pint --test` (stile) -> `phpstan analyse Modules` (gate).

## Cosa NON fare

- Non " sistemare" un file perche' `grep` lo segnalava 10 minuti fa: il file puo' essere gia' a posto
  o essere stato riscritto da un altro agente.
- Non fidarsi di un subagent che restituisce output vuoto: verificare con `find -newermt` e
  `find -name '*.lock'` se ha lavorato. Al **secondo** fallimento, fare da coordinatore.
- Non creare chiavi di traduzione in una lingua dove il file non esiste, e non rimuovere mai chiavi.
- Non introdurre `EmailInput`-like componenti per campi ripetuti con configurazione divergente:
  soglia = "ripetuto in 3+ superfici **con configurazione identica**".

## Acceptance criteria

- [ ] `php -d memory_limit=2G ./vendor/bin/phpstan analyse Modules` -> `[OK] No errors`
- [ ] `parallel-lint --exclude vendor --exclude .git Modules` -> 0 parse error in `.php` veri
- [ ] `pint --test` verde sui file toccati dalla campagna
- [ ] nessun lock residuo acquisito da questa campagna
- [ ] ogni correzione ha una riga di commento che spiega **perche'** e non **cosa**
- [ ] docs moduli e temi aggiornati dove la lezione e' riutilizzabile
