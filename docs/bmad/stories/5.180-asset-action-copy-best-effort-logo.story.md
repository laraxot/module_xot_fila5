# 5.180 — Regressione: URL grezzo `ptv::img/…` sul login

## Sintomo (live)

HTML login: `src="…/ptv::img/icon.png"` → **404**.
File pubblicato `/assets/ptv/img/icon.png` → **200**.

Segnalato da analisi agent dopo 5.178 (PNG magic): non basta riparare i byte
del PNG se `AssetAction` throw e `MetatagData` fa `asset('ptv::img/icon.png')`.

## Root cause

Fuori da `production`, `forceCopy=true` → ogni request ritenta `File::copy`.
Sotto `www-data`, se il file in `public_html` è di altro owner, copy fallisce
→ throw → fallback URL modulo grezzo.

Il claim `docs/chat/claim-public-path-public-html.md` (2026-09-01) aveva già
il fix; **non era più nel working tree**.

## Fix

1. `AssetAction::copyAsset`: se copy fallisce ma `$to` esiste ed è leggibile → return
2. `MetatagData::fallbackPublicAssetUrl`: mai `asset('mod::…')` (nome canonico post-merge 5.181)
