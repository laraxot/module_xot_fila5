# Story 5.223 — Logo assente su `/admin/login`

## Perché

Su `http://personale2022.prov.tv.local/admin/login` il logo Filament
non si vede. Ipotesi utente: Git LFS. Verifica sul codice: **no**.

`icon.png` in `Modules/Ptv/resources/img/` e in
`public_html/assets/ptv/img/` è un PNG reale (magic `89 50 4E 47`,
536×782, 8897 byte). `git lfs` non c'entra: policy no-LFS, file già blob.

## Causa

HTML servito da Apache/`www-data`:

```
src="http://personale2022.prov.tv.local/ptv::img/icon.png"  → 404
```

`/assets/ptv/img/icon.png` esiste e risponde 200. `public_path()` è
`public_html`. `AssetAction` in `APP_ENV=local` forza `File::copy` a
ogni request; dest `664` di `msottana` → `www-data` non può sovrascrivere
→ warning/`ErrorException` → `MetatagData::getBrandLogo()` catch →
`asset('ptv::img/icon.png')`.

Regressione di `5.56-public-path-public-html-e-logo-admin`: il claim
diceva best-effort se dest esiste; `copyAsset` in codice non lo faceva.

## AC

- [x] Diagnosi: PNG reale, LFS escluso, URL grezzo `module::` in HTML
- [x] `AssetAction::copyAsset`: se dest esiste e non è scrivibile, non copiare
- [x] Se copy fallisce ma dest è leggibile, continua
- [x] `MetatagData` non chiama `asset()` su notazione `module::`
- [x] Pest su AssetAction (skip runtime su host `10.100.200.15`)
- [x] Curl login: `src` contiene `/assets/ptv/img/icon.png`, non `ptv::`
