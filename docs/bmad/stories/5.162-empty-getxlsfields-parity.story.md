# 5.162 — campi vuoti, stesso file

## Story

As a valutatore,
I want that `export_xls` and `export_xls1` behave the same when `getXlsFields()` returns `[]`,
so that I never get a dump of every model attribute on one button and an empty sheet on the other.

## Perche'

`IndennitaResponsabilitaResource::getXlsFields()` torna `[]` se manca l'anno
(`anno/valutatore.anno` e `anno_valutatore.anno` entrambi null).

| Canale | Oggi se `$fields === []` |
|---|---|
| `export_xls` → `CollectionExport::map()` | dump di **tutti** gli attributi del model (`SafeArrayByModelCastAction`) |
| `export_xls1` → `XotBaseExporter::resolveColumns()` | **zero** colonne |

Non e' lo stesso contenuto. Sul filtro `anno=2026` del prompt 03 non scatta;
scatta se qualcuno esporta senza anno.

**Non** inventare `getXlsColumns()`. Contratto unico: `getXlsFields()`.

## Acceptance Criteria

1. Se `getXlsFields($filters)` e' `[]`, **entrambi** i canali producono lo stesso esito (stesse colonne, stessi valori — anche se l'esito e' "nessuna colonna").
2. Nessun dump silenzioso di attributi Eloquent (hidden, json, password, morph).
3. Test unitario Xot (senza DB): stesso `getXlsFields([])` → headings CollectionExport === label exporter (lista vuota o stessa lista esplicita).
4. PHPStan max 0 sui file toccati. Pest skip se DB `10.100.200.53`.
5. Non toccare `phpstan.neon`. Mai `@phpstan-ignore` come fix.

## Tasks

- [ ] Leggere `CollectionExport::map()` ramo `empty($this->fields)` e `XotBaseExporter::resolveColumns()`
- [ ] Decidere un solo fallback: lista vuota (consigliato) **oppure** campi base statici dichiarati nel Resource — non "tutti gli attributi"
- [ ] Allineare i due rami
- [ ] Test in `XotBaseExporterTest` / `CollectionExportLabelledFieldsTest`
- [ ] PHPStan sui file toccati

## Dev Notes

- `ExportXlsAction` passa sempre `$fields` da `getXlsFields`; `[]` e' esplicito, non `null`.
- `CollectionExport` tratta `null` e `[]` uguali: e' la trappola.
- IR: se si vuole esportare i 12 campi base anche senza anno, il fix sta in `getXlsFields()` (non ritornare `[]`), non nel fallback Xot.
