## Story

Come manutentore della piattaforma,
voglio che la guardia sui nomi di installazione veda le violazioni vere,
cosi' che «test verde» significhi «non ci sono violazioni» e non «non le sto cercando».

## Il fatto

Trigger: `Modules/Rating/README.md` diceva «Laraxot / FixCity Platform». La regola esiste,
e' completa e ha una guardia a tetto decrescente. Non ha visto niente, per due motivi
indipendenti.

### 1. Cercava il segnaposto invece dei nomi

```php
function hostProjectNames(): array
{
    return ['<nome progetto>', '<nome progetto>'];
}
```

`<nome progetto>` e' la stringa con cui si **bonifica**: la guardia contava i file gia'
sistemati. Il docblock diceva gia' dove i nomi devono vivere — «elencarli in un documento
agnostico sarebbe la violazione che il documento vieta» — ma la regola e' stata applicata
**al file della guardia**, che non e' documentazione di modulo.

Il caso generale, che vale oltre questo file: **una regola applicata al proprio meccanismo
di verifica lo disattiva**, e lo fa in silenzio, perche' il test resta verde.

### 2. Il perimetro escludeva i README

```php
if (! str_contains($path, '/docs/')) {
    continue;
}
```

`Modules/*/README.md` era fuori dal controllo: 17 di essi nominano un'installazione, ed e'
il primo file che si legge quando un modulo viene riusato altrove.

## Acceptance Criteria

1. `hostProjectNames()` contiene i nomi reali delle installazioni note.
2. Il perimetro copre ogni `.md` di modulo e tema, non solo `/docs/`.
3. `vendor/`, `node_modules/` e `graphify-out/` restano esclusi.
4. Il tetto e' rimisurato su cio' che la guardia conta **adesso**, e la differenza col
   valore precedente e' spiegata.
5. Il test passa.
