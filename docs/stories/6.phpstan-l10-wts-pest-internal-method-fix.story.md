## Executive Summary

Wts module: 494 PHPStan L10 errors. Root cause: Pest framework internal methods (e.g., `toBe()`) in `Expectation` class marked `internal` — cannot be called from outside `Pest` namespace.

Similar issue resolved in prior sessions (Pest plugin + Larastan patches). This story coordinates fix across test suite.

## Problem Statement

```
494 errors in Modules/Wts/tests/

Error pattern:
  Call to method toBe() of internal class Pest\Mixins\Expectation<TValue>
  from outside its root namespace Pest
  🪪  method.internalClass
```

Trigger files:
- `tests/Feature/WtsWarehouseAndMaterialDetailTest.php` (multiple lines)
- Other test files using Pest assertion methods

## Root Cause

Pest 5.x marks certain mixin methods as internal. PHPStan strict analysis (L10) enforces namespace boundaries. Test code calls internal methods without proper extension pattern.

## Solution Strategy

**Option A: Type-wrapper extension** (preferred)
- Create `Tests/Expectations/WtsExpectation` extending Pest\Expectation
- Wrap internal methods with public facade methods
- Update test files to use facade instead of direct calls

**Option B: Pest plugin upgrade**
- Check if newer Pest version (5.2+) relaxes internal boundary for testing
- Or update phpstan-pest-plugin to handle test namespace exception

**Option C: Add ignoreErrors temporarily**
- Document why internal methods are required for tests
- Add targeted ignoreErrors entries for test files
- ⚠️ Not preferred — masks architectural debt
