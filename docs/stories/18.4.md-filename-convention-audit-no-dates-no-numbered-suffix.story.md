## Regola (utente, 2026-09-07)

"I file .md seguono delle convenzioni che non stai rispettando: nei nomi dei
file .md non ci devono essere ne' date ne' timestamp ne' finire per -1.md
-2.md." Regola canonica gia' esistente e documentata:
`bashscripts/ai/wiki/rules/docs-chat-filename-no-dates.md` (niente date, in
nessuna posizione del filename — prefisso, mezzo o coda — sposta la data nel
frontmatter YAML o in una sezione dedicata) e
`bashscripts/ai/wiki/rules/no-numbered-filenames.md` (bridge verso un
canonico che risulta rotto/auto-referenziale — segnalato sotto).

## Audit di scope (2026-09-07) — NON eseguito, solo misurato

```bash
find docs/chat -iname "*.md" | grep -E "[0-9]{4}-[0-9]{2}-[0-9]{2}" | wc -l
# 35 file in docs/chat/ con data nel nome (oltre a quello gia' corretto)

find laravel/Modules -path "*/docs/*" \( -iname "*-[0-9].md" -o -iname "*-[0-9][0-9].md" \) | \
  sed -E 's#(laravel/Modules/[^/]+)/.*#\1#' | sort | uniq -c | sort -rn
```

Risultato: **~3800 file** `.md` con suffisso numerico (`-1.md`, `-2.md`, ...)
sotto `laravel/Modules/*/docs/` e **336** sotto `laravel/Themes/*/docs/`.
Concentrazione principale: Xot (832), Notify (727), User (684), Lang (139),
Cms (104), UI (83), Job (72), Media (65), Geo (62), Activity (46) — il resto
dei moduli sotto 10 ciascuno.

## Perche' non e' stato eseguito in questa sessione

Rinominare ~4200 file (`git mv` uno a uno, o script) richiede anche:
1. Verificare ogni cross-reference interno (README, INDEX.md, link relativi
   tra doc) prima di rompere qualcosa — con questo volume, un grep singolo
   non basta, serve un tool dedicato con verifica post-rename.
2. Capire se i suffissi numerici sono davvero "duplicati incrementali" (il
   caso che la regola vuole vietare) o versioni intenzionalmente distinte
   (es. `chart-components-1.md` come continuazione di un file troppo lungo
   gia' diviso) — serve leggere un campione per modulo prima di decidere la
   strategia di merge/rinomina.
3. E' un lavoro quasi interamente cosmetico/storico (non blocca PHPStan, non
   e' un bug funzionale) su una scala 100x piu' grande di qualunque altra
   task di igiene affrontata oggi (confronta con la story 18.3, dove il
   limite "max 6 .md in root" era gia' rispettato ovunque con zero azioni
   necessarie — qui invece il volume e' enorme e reale).

## Raccomandazione

Trattare come iniziativa dedicata, non come task ad hoc dentro un'altra
sessione: campionare 2-3 moduli (Xot, Notify, User — i piu' grandi) per
capire il pattern reale dei suffissi numerici, poi decidere script vs
manuale, poi eseguire modulo per modulo con verifica link prima di ogni
commit. Non avviato senza una decisione esplicita del proprietario data la
scala.
