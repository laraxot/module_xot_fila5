# Story 5.103: Pattern Documentation Error Correction

## Contesto

User feedback su errore nel design doc `hasxottable-reorderable.md`:
- Esempio con `use HasXotTable` in Resource
- Esempio con `public function orderColumn(): string` 
- Override in Resource invece che Table

## Errori Identificati

### Errore 1: `use HasXotTable` in Resource
**Cosa ho scritto:**
```php
class CategoriaResource extends XotBaseResource
{
    use HasXotTable;  // SBAGLIATO
}
```

**Perché è sbagliato:**
- Resources estendono XotBaseResource
- XotBaseResource delega a XotBaseResourceTable
- XotBaseResourceTable usa HasXotTable
- Resources NON devono usare direttamente HasXotTable

**Correzione:**
```php
// Niente use HasXotTable nelle Resources
// Override nella Table class:
class MyTable extends XotBaseResourceTable
{
    protected function getOrderColumn(): ?string
    {
        return 'custom_sort_field';
    }
}
```

### Errore 2: `public function orderColumn(): string`
**Cosa ho scritto:**
```php
public function orderColumn(): string  // SBAGLIATO
{
    return auth()->user()->can('admin') ? 'priority_order' : 'standard_order';
}
```

**Perché è sbagliato:**
- Viola le convenzioni getter del progetto (get + PascalCase)
- Progetto usa rigorosamente `get` + PascalCase per tutti i getter
- Nessun metodo "bare" per configurazione nel progetto

**Correzione:**
```php
protected function getOrderColumn(): ?string
{
    return auth()->user()->can('admin') ? 'priority_order' : 'standard_order';
}
```

### Errore 3: Override in Resource invece che Table
**Cosa ho scritto:**
```php
class CategoriaResource extends XotBaseResource
{
    public function orderColumn(): string  // SBAGLIATO
    {
        // ...
    }
}
```

**Perché è sbagliato:**
- Resources delegano a Table classes
- HasXotTable è usato da XotBaseResourceTable
- Override deve essere nella Table class concreta

**Correzione:**
```php
// In laravel/Modules/MyModule/app/Filament/Resources/MyResource/Tables/MyTable.php
class MyTable extends XotBaseResourceTable
{
    protected function getOrderColumn(): ?string
    {
        return 'custom_sort_field';
    }
}
```

### Errore 4: Non sincronizzato correzioni tra ADR, design doc e stories
**Cosa ho fatto:**
- Ho corretto il design doc in Xot ma NON l'ADR in IndennitaResponsabilita
- L'ADR conteneva ancora `setOrderColumn()`, property, `$this->hasColumn()`
- L'ADR usava `$model->getConnection()->getSchemaBuilder()->hasColumn()` invece di `\Schema::hasColumn()`

**Perché è sbagliato:**
- I documenti devono essere allineati
- User ha corretto le stories usando `\Schema::hasColumn()` e `app(static::getModel())`
- Non ho letto i diff dell'utente per capire le correzioni

**Correzione:**
- ADR aggiornato con pattern corretto
- Design doc aggiornato con pattern corretto
- Aggiunto rationale nel ADR per spiegare le scelte
- Story 5.104 creata per tracciare errore di sincronizzazione

### Errore 5: Proposto duplicazione codice con hasOrderableColumn()
**Cosa ho fatto:**
- Ho proposto di definire `hasOrderableColumn()` helper method
- Story 5.92 usava `hasOrderableColumn()` helper method
- Design doc e ADR documentavano questo metodo

**Perché è sbagliato:**
- `hasColumn()` esiste già in `XotBaseMigration` (ma non in `HasXotTable`)
- Definire `hasOrderableColumn()` duplicherebbe codice inutilmente
- DRY violato - usare direttamente `\Schema::hasColumn()` in `getOrderColumn()`

**Correzione:**
- Design doc rimosso hasOrderableColumn() helper
- ADR rimosso hasOrderableColumn() helper
- Story 5.92 rimosso hasOrderableColumn() helper
- Story 5.104 aggiornata per tracciare errore

## Root Cause

1. **Non ho analizzato XotBaseResource** prima di scrivere esempi
2. **Non ho verificato i pattern getter/setter** nel progetto
3. **Non ho capito l'architettura di delegazione** Resource → Table → Trait

## Prevenzione

Prima di scrivere esempi di codice:
1. Analizzare la classe base (XotBaseResource, XotBaseResourceTable)
2. Verificare le convenzioni naming (getter: get + PascalCase)
3. Capire l'architettura di delegazione (chi estende chi)
4. Cercare esempi reali nel progetto
