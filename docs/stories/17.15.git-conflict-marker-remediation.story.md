# 17.15: Git conflict marker remediation — Xot

## Story

As a maintainer, I want Xot's committed git conflict markers removed with the correct side
chosen per hunk, so that `phpstan analyse Modules` and `pest` stop crashing at bootstrap — Xot
is the base module every other module's TestCase/PanelProvider/Resource extends, so this blocks
the entire monorepo, including the sibling fix already done in Notify (story 4.25), whose own
Pest run cannot execute because `Modules/Xot/tests/XotBaseTestCase.php` itself is broken.

## Root Cause (verified on code, not docs)

Same disease as [[4.25.git-conflict-marker-remediation]] (Notify), independently confirmed here:
- Xot HEAD (`25b12f2f`) is a merge commit (`Merge: 6f9194a0 0ccfbfc1`) of two commit graphs with
  **no common ancestor** (`git merge-base 6f9194a0 0ccfbfc1` returns nothing) — committed with
  literal `<<<<<<<`/`=======`/`>>>>>>> laraxot/dev` markers left inline.
- Scope: 663 `.php` files, 1230 conflict blocks (bigger than Notify's 143 files / 410 blocks —
  Xot is the larger, foundational module).
- Per `git-forward-only` rule: no `reset`/`revert`/`checkout`. Forward patch only.

## Acceptance Criteria

<!-- LOCKED -->
1. Zero `<<<<<<<`/`=======`/`>>>>>>>` markers remain in any `Modules/Xot/**/*.php` file.
2. Every hunk resolved by studying both sides and picking the version matching current, verified
   architecture — not a blind "ours always wins". Expected recurring patterns (confirm per hunk,
   don't assume blindly from the Notify precedent):
   - `mixed $x` narrowed to a concrete type (matches project's ADR-011 "narrow mixed" rule) wins.
   - `#[Override]` active beats `// #[Override]` commented out, where the method genuinely
     overrides a parent/interface member.
   - Style-only hunks (parens on `new X()`/`new X`, whitespace, import order) resolved
     deterministically, then normalized by `./vendor/bin/pint` (`pint.json` at repo root).
   - Any hunk that is a genuine behavioural fork with no way to determine correctness from
     current source is resolved to keep the working/current (`ours`) side and flagged explicitly
     in this story's Dev Notes for human follow-up — not guessed silently.
3. `php -l` passes on every touched file; `phpstan analyse Modules` no longer crashes at the
   Laravel/Filament bootstrap stage for Xot (it already doesn't for Notify since 4.25).
4. `./vendor/bin/pint Modules/Xot` run after resolution (whole-module run accepted precedent:
   see 4.25 Dev Notes — Boost's own convention is unconditional `pint --dirty` before finalizing,
   not file-scoped).
5. `./vendor/bin/pest Modules/Xot` and `./vendor/bin/pest Modules/Notify` both at least execute
   (no parse/bootstrap crash) — full green is NOT required by this story; pre-existing failures
   are listed, not silently introduced. Capture failing test names before/after this story's
   changes where feasible (addresses the falsifiability gap flagged in 4.25's validation review).
6. New commit(s) only. `laraxot/dev`'s unrelated-history reconciliation stays explicitly out of
   scope (human decision).
7. Given the volume (663 files), work is fanned out across parallel subagents by directory/area;
   this story's Dev Notes record which agent resolved which batch and any hunks it could not
   confidently resolve, for a single coordinated final verification pass (not per-agent commits).
