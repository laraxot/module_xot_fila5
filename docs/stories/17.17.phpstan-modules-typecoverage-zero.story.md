## User story

Come **maintainer del monorepo TecnicalPlanner**,
voglio **`phpstan analyse Modules` a zero errori sull'albero intero**,
così che **il gate di qualità torni verde senza toccare alcun file `.neon`**.

## Contesto (Analysis, 2026-09-03)

Ground truth: un solo run full-tree con `--error-format=json`.

```bash
cd laravel && ./vendor/bin/phpstan analyse Modules --memory-limit=-1 --error-format=json
# file_errors: 116
```

| Identifier | Conteggio |
|---|---|
| `typeCoverage.paramTypeCoverage` | 111 |
| `missingType.generics` | 3 |
| `trait.unused` | 2 |

Distribuzione `paramTypeCoverage` per modulo: User 76, Cms 11, Employee 10, Lang 10, Job 4.

Messaggio ripetuto su ogni parametro non tipizzato:

```
Out of 10583 possible param types, only 10472 - 98.9 % actually have it.
Add more param types to get over 99 %
```

Il conteggio degli errori coincide con il numero di parametri non tipizzati nell'albero
analizzato: 10583 - 10472 = 111. Per superare il 99 % basterebbero 6 parametri
(10478 / 10583 = 99,01 %), ma fermarsi lì lascia 105 parametri di debito silenzioso che
nessun gate per modulo può vedere. **Obiettivo: 100 %, tutti e 111 tipizzati.**

Precedente diretto: `bashscripts/ai/wiki/memories/typecoverage-global-threshold-full-tree-only.md`
documenta che `tomasvotruba/type-coverage` — tirato dentro transitivamente da
`pest-plugin-type-coverage` via `extension-installer`, quindi non disattivabile commentando
gli `includes:` — calcola la percentuale **sull'albero passato al comando**. Un subagent che
chiude `Modules/Xot` non può vedere il deficit dell'albero intero.

## Obiettivi

1. Tipizzare nativamente tutti i 111 parametri elencati nel run full-tree.
2. Dichiarare `@use HasXotFactory<TModel>` sui 3 model User che usano il trait generico Xot.
3. Risolvere i 2 `trait.unused` alla radice (trait realmente morto vs. trait non referenziato
   perché il consumatore è stato rimosso), senza sopprimere.
4. Riportare il run full-tree a `file_errors: 0` ed exit code 0 insieme.

## Vincoli non negoziabili

- **Nessuna modifica a `phpstan.neon`, `phpstan-baseline.neon` o qualunque altro `.neon`.**
  Owner unico è l'utente. Niente `-c`, niente baseline rigenerata.
  Rif. memory `feedback_neon-files-hands-off`.
- Nessun `@phpstan-ignore`, nessun `mixed` di comodo per far sparire il messaggio: un
  parametro tipizzato `mixed` conta come tipizzato ma non aggiunge informazione — usarlo solo
  dove la firma del parent lo impone davvero.
- Parametri LSP-guarded (override di firme parent non tipizzate, implementazioni di interfacce
  di terze parti) non vanno forzati: il collector di type-coverage li salta già. Verificare
  leggendo la firma del parent prima di dichiarare un parametro non fixabile.
- Lock `bashscripts/lock/lock.sh` su ogni file prima dell'edit, `unlock.sh` a fine task.

## Testing

- Gate primario: `./vendor/bin/phpstan analyse Modules --memory-limit=-1` (full-tree).
- Gate per modulo: `./vendor/bin/phpstan analyse Modules/<Mod> --memory-limit=-1`.
- Regressione runtime: `./vendor/bin/pest Modules/<Mod>` sul modulo intero — aggiungere un
  tipo di parametro non deve cambiare comportamento, ma un tipo **sbagliato** su un callback
  Filament o su una closure Eloquent produce `TypeError` solo a runtime, quindi il test è
  necessario, non opzionale.

## Esito (2026-09-03)

`phpstan analyse Modules --memory-limit=-1` → `[OK] No errors`, exit code 0, `file_errors: 0`.

Percorso reale: 116 → 5 → 0. I 5 intermedi non erano una regressione: tipizzare i parametri
ha permesso a PHPStan di analizzare più a fondo e di far emergere errori che prima non
raggiungeva (`argument.type` sulla contro-varianza di `Collection::sortBy`, un `return.type`
su `Str::of()->append()` che restituisce `Stringable` e non `string`, due
`instanceof.alwaysTrue` diventati ridondanti proprio grazie al tipo dichiarato, un
`@use RelationX<Model>` su un trait non generico).

Tre decisioni degne di nota:

- **`$state` resta `mixed`.** Verificato su `filament/filament` v5.7.6:
  `HasState::getState(): mixed`. Non è una scorciatoia, è il contratto del framework.
- **`$record` è `Model|array|null`, non `?Model`.** `BelongsToModel::getRecord()` e
  `Tables\Columns\Concerns\HasRecord::getRecord()` restituiscono anche `array`.
- **Due trait morti rimossi invece che silenziati.** `User\Models\Traits\IsProfileTrait`
  (il commit `d2bedd07` di oggi lo aveva già staccato da `BaseProfile` dichiarandolo dead
  code, ma aveva lasciato il file) e `User\Tests\Support\CreatesApplication` (duplicato
  più debole del canonico `Xot\Tests\CreatesApplication`, referenziato da nessuno).

I test Pest per modulo falliscono per cause ambientali preesistenti e indipendenti da questo
lavoro (`SQLSTATE[HY000] ... no such table: job_batches`: migrazioni assenti nello sqlite di
test). Non introdotti qui e non risolti qui.
