# Story 01.34 — Una migrazione owner per modello (repo-wide)

## Perché

N `create_*` sulla stessa tabella nello stesso modulo → ordine migrate ambiguo, schema
frammentato, onboarding impossibile. Religione: **1 modello = 1 file** in
`database/migrations/` (top-level). I loser si **eliminano** (`git rm`); l'archivio è git,
non cartelle `_archive_redundant/` / `_bak/`.

## Acceptance criteria

- [x] Zero duplicati `*_create_{table}_table.php` attivi per `(modulo, tabella)`
- [x] Zero `add_*` / `update_*` / `fix_*` attivi top-level
- [x] Nessuna cartella `_archive_redundant` / `_bak` sotto `migrations/`
- [x] Audit script `bashscripts/tools/migrations/audit-duplicate-create-migrations.sh` exit 0
- [x] Docs Xot + memoria + claim aggiornati
- [x] Cross-module stesso nome tabella documentato come debito (connection-aware)

## Fuori scope (wave successiva)

Risolvere ownership cross-modulo (`stabi_dirigentes`, `categoria_propro`, …) solo dopo
verifica connection/DB reale per modulo.

## Dev notes

- Dati sacri: niente `migrate:fresh` / `--force`; bump solo dove lo schema owner era
  incompleto rispetto ai duplicati.
- Host `10.100.200.15`: niente Pest.
