## User story

Come **maintainer del monorepo TecnicalPlanner**,
voglio **`phpstan analyse Modules` a zero errori senza toccare i file `.neon`**,
così che **il gate di qualità torni verde e nessun falso negativo nasconda difetti reali**.

## Contesto (Analysis)

Ground truth: misura esatta da eseguire all'inizio della story.

```bash
cd laravel && ./vendor/bin/phpstan analyse Modules --memory-limit=-1 --error-format=json
```

**Baseline misure precedenti:**
- Story 17.17 (2026-09-03): `file_errors: 0`, `typeCoverage.paramTypeCoverage` → 100%
- Story 17.14 (2026-08-28): ridotto da 443 a 0 errori nel cluster Modules

**Stato attuale da verificare:** Verificare quanti errori rimangono e quale sia la distribuzione
per identifier.

## Obiettivi

1. Eseguire baseline misura piena (JSON + exit code).
2. Tipizzare tutti i parametri non tipizzati, narrowing su `mixed`, risolvere union types non espliciti.
3. Nessun `@phpstan-ignore` se non per falsi positivi Pest documentati inline.
4. Riportare `phpstan analyse Modules` a `file_errors: 0` ed exit code 0.
5. Aggiornare il second brain con risultati e nuove regole scoperte.

## Vincoli non negoziabili

- **Nessuna modifica a `phpstan.neon`, `phpstan-baseline.neon` o qualunque altro `.neon`.**
  Owner unico è l'utente. Niente `-c`, niente baseline rigenerata.
- Nessun `@phpstan-ignore` massivo: eccezione solo per `method.internalClass` Pest
  (inline, con identifier e motivo documentati).
- Nessun `mixed` di comodo: narrowing, type guards, generics, union types.
- Lock `bashscripts/lock/lock.sh` su ogni file prima dell'edit, `unlock.sh` a fine task.
- Git forward-only: niente revert/reset; i test sono artefatti permanenti.
