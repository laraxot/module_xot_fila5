# XOT-5.52 — Risoluzione collisioni committate in Xot e Notify

## GitHub (tracciamento)

| Artefatto | URL |
|---|---|

La story è posseduta da Xot perché il gate, il protocollo di risoluzione e il second brain
sono infrastruttura condivisa; Notify resta nel perimetro operativo come modulo consumatore.

## User story

Come **maintainer del monorepo TechPlanner**,
voglio **eliminare i marker di conflitto committati nei submoduli Xot e Notify**,
così che **`phpstan analyse Modules` torni a girare (oggi muore con parse error su `Xot/helpers/Helper.php:6`) e il tree sia di nuovo poesia**.

## Contesto (Analysis, 2026-09-03)

Diverso da STORY-GIT-001: lì i conflitti erano *unmerged nel working tree*; qui sono
**committati** — i marker vivono nella storia (HEAD), non in un merge in corso. Il
working tree è inoltre già sporco per attività concorrenti: i conteggi vanno quindi
registrati per ogni run e non trattati come una baseline immutabile.

- Censimento corrente fence-aware (working tree): **1.296 file Xot** e **166 file
  Notify**, con **795 file orfani** complessivi. Il risultato può cambiare mentre
  altri agenti lavorano e deve essere rieseguito prima di ogni batch.
- Ricostruzione su HEAD committato: **1.990 file Xot** e **312 file Notify**, con
  **792 orfani** complessivi. Questi numeri descrivono la contaminazione committata,
  non autorizzano a sovrascrivere modifiche locali concorrenti.
  L'upstream `laraxot/dev` (`e50b8d58`) ha la STESSA contaminazione (673 file identici).
- `Modules/Notify`: analogo, merge `52abdac1` — **258 file** (57 php, 200 md, 1 .old).
- Lati dei conflitti: `HEAD` vs `laraxot/dev`. Entrambi i genitori sono sani:
  la fusione semantica è sempre possibile confrontando con i genitori.
- `.gitattributes` di Xot aveva un conflitto alla riga 6-10 che rompeva OGNI comando
  git nel submodulo (`laraxot/dev is not a valid attribute name`): risolto per primo.
- **Seconda famiglia di marker** (QA): label `.merge_file_XXXXXX` — conflitti di una
  generazione PRECEDENTE al merge 25b12f2f, alcuni malformati/annidati (es.
  `docs/module-structure.md` senza `=======`). Per questi i genitori NON sono sani:
  fallback = ricostruzione semantica manuale, non `git show parent`.
- **Contaminazione cross-progetto** (QA): ~66 md con `ptv::`/`fixcity::`/`FixCity`/
  placeholder `<nome progetto>` — AC5 esteso ai CONTENUTI, non solo ai path.
- **Sessioni concorrenti attive**: rileggere ogni file prima di scriverlo,
  ri-inventariare prima di ogni batch (wiki §"Sweep concorrenti").
- Scope: SOLO submoduli locali. Upstream `laraxot/dev` deciso dopo con l'utente.

## Strategia di risoluzione (Solutioning)

Ordine di precedenza per ogni blocco di conflitto:

1. **Corruzione perde sempre** (troncamenti, doppi header, placeholder) — wiki sweep §criteri.
2. **PHP**: fondere semanticamente; a parità di semantica preferire la variante più
   type-safe/PHPStan-friendly (es. `preg_match(...) !== 1` con Safe, guardie esplicite).
   Se un lato aggiunge funzionalità (es. stub Pest, `getRouteParameters`) e l'altro no:
   tenere ENTRAMBI i contributi se compatibili.
3. **Import/use**: unione dei due lati, dedup, ordinati come da convenzione file.
4. **Markdown**: marker dentro fence ``` sono ESEMPI, non toccarli. Front matter in testa.
   Doppi `updated:` → tenere il più recente.
5. **Config (json/xml/neon/gitignore)**: fusione + validazione parser.
6. **In dubbio irrisolvibile**: confrontare con i genitori — Xot: `6f9194a0` (HEAD-side)
   e `0ccfbfc1` (laraxot-side); Notify: entrambi i parent di `52abdac1`
   (`git -C <mod> log --format=%p -1 <merge>`) — `git show <parent>:<path>`.

Criteri wiki da applicare (da `git-merge-marker-sweep.md` + memorie):
- Filament `getTableColumns`: corpo HEAD, firma instance (no static).
- LFS (policy 2026-08-03): contenuto reale batte SEMPRE il puntatore LFS.
- YAML: vince lo scalare quotato; front matter sempre in testa al file.
- Checkbox `[x]` valida solo se l'artefatto citato esiste nel repo.
- `PanelMixin`: delega al resolver statico, mixin registrato in
  `XotServiceProvider::registerFilamentPanelMacros()`.
- Marker ORFANI (start/end sbilanciati): ricostruire dal confronto coi genitori,
  non indovinare il blocco.

## Esecuzione (Implementation)

- Risoluzione **in-place sul working tree** (decisione utente): nessun redo del merge,
  nessuna riscrittura storia, nessun push.
- **Manifest unico** generato upfront dallo scanner (`.qwen/tmp/conflict-files.txt`),
  partizionato deterministicamente per prefisso di path (disgiunzione garantita):
  ~20–30 file/batch per `.php` (fusione semantica costosa), ~60–80 per `.md`,
  blade/config in batch dedicato. Nessun file in due batch.
- Verifica finale centralizzata (AC1–AC6) dal main agent, non dai subagenti.
- **Loop PHPStan** (AC4): `while errori > 0`: raggruppa errori per file → batch di fix
  → re-run. Budget max 5 iterazioni; stop-rule se gli errori non calano tra due run
  → escalation all'utente con report. La rimozione marker è necessaria, non sufficiente.
- Commit: **solo su richiesta esplicita utente** (regola progetto).

## Rischi

- Sweep cieco su md distruggerebbe la documentazione didattica (fence-aware obbligatorio).
- Volume (2.294 file): serve batching disciplinato + verifica indipendente.
- PHPStan L10: la fusione "che compila" non basta, deve essere anche type-clean.

## Verifica

```bash

python3 bashscripts/git/conflict-marker-census.py laravel/Modules/Xot laravel/Modules/Notify
# AC2 — path prefissati, non git diff (i fix possono venir committati in corsa)
(cd laravel/Modules/Xot && git status --porcelain | awk '{print $2}' \
  | grep '\.php$' | xargs -r -n1 php -l)
# Smoke-test .gitattributes (nessun warning "not a valid attribute name")
git -C laravel/Modules/Xot check-attr -a README.md
# AC4
cd laravel && ./vendor/bin/phpstan analyse Modules
```

Loop di iterazione: se AC4 fallisce dopo la rimozione marker (fusione sbagliata),
si torna al file incriminato con la precedenza 6 (confronto genitori) e si ripete
fino a zero errori. La rimozione marker è condizione necessaria, non sufficiente.
