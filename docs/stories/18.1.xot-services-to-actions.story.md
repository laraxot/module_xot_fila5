# Xot: app/Services -> app/Actions

## Why

`Modules/Xot/app/Services/` (31 files) violated `no-services-rule.md`
("RELIGION", no exceptions): business logic and collaborator classes must
live under `app/Actions/`, grouped by context, and every real use-case class
must use `Spatie\QueueableAction\QueueableAction` with a single `execute()`
entrypoint.

## Collision with a concurrent live session (read this first)

While working this story, another session was **simultaneously converting
the exact same `Modules/Xot/app/Services/*` scope**, using a flat/root
naming convention (`app/Actions/ArtisanAction.php`,
`app/Actions/ModuleAction.php`, `app/Actions/ConfigAction.php`, etc.)
instead of the context-grouped shape this rule requires. Evidence:

- Several of its files were caught **mid-edit and syntactically broken**
  for the entire duration of this session: `Actions/ConfigAction.php`,
  `Actions/ModuleAction.php`, `Actions/XotServiceAction.php`,
  `Actions/Artisan/Handlers/CacheCommandHandlerAction.php`,
  `Actions/Artisan/Handlers/DebugbarCommandHandlerAction.php` (all
  `Unexpected token: implements` / `unexpected '{'` — a script inserted
  `use QueueableAction;` plus a stray `{` without finishing the merge).
- Two of its "finished" (syntactically valid) files have a real bug: the
  **file was renamed but the class inside was not**.
  `app/Actions/ArtisanAction.php` still declares `class ArtisanService`,
  and `app/Actions/RouteDynAction.php` still declares `class RouteDynService`
  — so `Modules\Xot\Actions\ArtisanAction` and
  `Modules\Xot\Actions\RouteDynAction` do not actually exist as classes.
  Confirmed via `grep -n "^class" ` on both files and via PHPStan
  (`class.notFound` on every call site that references them).
- A lock file (`app/Services/RouteDynService.php.lock`,
  `app/Services/RouteService.php.lock`) plus assorted debris
  (`app/Services/cacheservice.md`, `trend.test`, `RouteService.php.bak`,
  `xotservice.php.no`, `FileService.ot_action`, a stray `bashscripts/`
  subtree, `composer.json`, `.gitignore`) sit directly in `app/Services/`,
  all gitignored (`app/Services/.gitignore` has `*.lock`, `*.bak`) and all
  pre-dating this session (timestamps Jul 16 - Sep 3). Left untouched —
  out of this story's `.php`-file scope, not created by this session.

**None of the above files were touched by this story.** Every new file this
story adds uses a distinct path/filename from that session's in-flight
files, specifically to avoid clobbering or racing its writes. Where that
session's work already fully superseded a Service (see "already done" rows
below), this story only deletes the `Services/*.php` source and updates
callers — it does not re-implement what was already correct.

## Classification (Kind A vs Kind B) and destination

Kind A = genuine multi-method "god service" facade -> one Action per
independent method. Kind B = Strategy/Handler/Adapter collaborator selected
by a registry/dispatcher, no real single `execute()` shape -> relocated as a
plain class subtree under `Actions/<Context>/`, not force-fit into
QueueableAction.

## Call sites updated

Whole-`Modules/` grep (not just Xot) for `Modules\Xot\Services`, every bare
class name (`ArtisanService::`, `new ConfigService`, etc.) found:

- `Modules/Xot/tests/Unit/XotArtisanCommandsHelpersCoverageTest.php` —
  removed `use Modules\Xot\Services\RouteService;`, replaced the
  `RouteService::class` reflection-sweep array entry with
  `Modules\Xot\Actions\Route\IsAdminRouteAction::class`.
- `Modules/Xot/tests/Unit/XotExecuteCoverage50Test.php` — removed
  `use Modules\Xot\Services\RouteService;`, replaced the
  `RouteService::inAdmin(...)` + reflection-sweep test body with two direct
  `app(IsAdminRouteAction::class)->execute(...)` assertions (the reflection
  sweep over all-of-RouteService's-static-methods no longer applies once
  the methods are split across 8 separate Action classes).
- `Modules/Xot/tests/Unit/Services/RouteDynServiceTest.php` — deleted,
  replaced by `Modules/Xot/tests/Unit/Actions/Route/GetRouteMethodActionTest.php`.
  Note: the original test's assertions (`getMethod(['method' => ['get', 1,
  'post']])` expected to return `['get', 'post']`) did **not** match the
  real implementation (`Arr::wrap()` never filters non-string values —
  verified by direct execution: `Arr::wrap(['get', 1, 'post'])` really
  returns `['get', 1, 'post']` unchanged). The new test asserts the actual,
  verified behaviour instead of carrying the false expectation forward.
- No cross-module (non-Xot) call sites exist for any of the 31 classes —
  confirmed by a repo-wide grep across all of `Modules/`. The one
  Tenant-module hit (`Modules/Tenant/app/Actions/Config/MorphMapConfigResolverAction.php:30`)
  is a historical code comment ("Ex `RouteService::inAdmin()` (Services
  archiviato)"), not a live reference. The one Limesurvey hit
  (`LimesurveyServiceProvider.php:9`) is a commented-out `use` statement
  for a `BladeService` class that was never part of this scope.
- `Modules/Xot/tests/Unit/Services/ArtisanServiceTest.php` — **left
  untouched**. Despite its path, it already tests
  `Modules\Xot\Actions\ArtisanAction` (the concurrent session's file, see
  collision section above), not `Modules\Xot\Services\ArtisanService`. Not
  a call site of anything this story deleted.
