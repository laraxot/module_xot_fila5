# 5.85 — getInfolistSchema() vietato su XotBaseViewRecord

## Regola (dichiarata dall'utente, confermata sul codice)

`XotBaseViewRecord` (`Modules/Xot/app/Filament/Resources/Pages/XotBaseViewRecord.php`)
NON dichiara `getInfolistSchema()` (verificato: zero match). Lo schema infolist vive
SOLO in `Schemas/{Model}Infolist.php` (estende `XotBaseResourceInfolist`), risolto da
`XotBaseResource::getInfolistClass()` + `infolist()` (final, static, riga 245).

Simmetrico alla regola già nota: chi estende `XotBaseResource` non deve avere
`getFormSchema()` (bridge legacy `getFormSchemaOld()` a parte); chi estende
`XotBaseResourceForm`/`XotBaseResourceInfolist` DEVE avere `getFormSchema()`/
`getInfolistSchema()`.

## Sintomo

29 Page con `#[Override] ... getInfolistSchema()` fanno **fatal error a bootstrap**
("has #[\Override] attribute, but no matching parent method exists") — bloccano
PHPStan/artisan/tutto per l'intero monorepo (stesso meccanismo dei marker 5.83: Laravel
boota tutti i service provider/Livewire component a prescindere dallo scope).
Altri 7 file hanno lo stesso metodo ma senza `#[Override]` — non bloccano il boot ma
violano comunque la regola.

## Metodo

Swarm per modulo/cluster. Per ciascun file:
1. Verificare che `Schemas/{Model}Infolist.php` esista già con `getInfolistSchema()`
   equivalente (nella stragrande maggioranza dei casi la Page fa un puro passthrough
   `return {Model}Infolist::getInfolistSchema();` — verificato su
   `ViewIndennitaResponsabilita.php`). Se il contenuto della Page è PIÙ RICCO di quello
   nello Schemas/*Infolist esistente, portare la differenza nello Schemas/*Infolist
   (non perdere campi), poi cancellare il metodo dalla Page.
2. Rimuovere il metodo `getInfolistSchema()` (+ `#[Override]`/`#[\Override]` +
   docblock) dalla Page.
3. Pulire import ora inutilizzati (`Component`, `Override`, componenti Filament usati
   solo lì).
4. `php -l` pulito.

Lock per file, nessun commit per agente (unico commit finale per modulo).

## Esito (2026-09-07)

38 file su 5 batch paralleli (Agent tool), tutti RESOLVED. Bootstrap PHPStan verde
(`php -r ... bootstrap() → BOOT OK`) dopo la chiusura di 5.83 (marker Xot) + 5.85
(questa story).

Scoperte non previste dal piano iniziale:
- **Bug sistemico**: molti `Schemas/*Infolist.php` non estendevano
  `XotBaseResourceInfolist` (avrebbero fallito `Assert::subclassOf` a runtime in
  `XotBaseResource::getInfolistClass()`) — corretto in batch-B/C dove trovato.
  Origine: commit iniziale `dd41b774` con stub generici id/name/created_at.
- **Campi persi**: in ~9 file la Page conteneva campi reali (relazioni Eloquent,
  cast array, `copyable()`, `formatStateUsing`) assenti dallo Schemas/*Infolist —
  fatti merge prima di cancellare la Page (batch-A/B/C/D/E, dettaglio nei report dei
  singoli agenti in `docs/chat/`).
- **Campi fantasma**: alcuni campi nella Page (`display_name` su Team, `role`/
  `tenant.name` su TenantUser) non corrispondevano a colonne/relazioni reali —
  scartati correttamente, non migrati.
- **Un fatal error reale** in `Modules/Media/.../Pages/ConvertMedia.php` (
  `#[Override]` orfano senza metodo, parse error) da un edit incompleto precedente —
  corretto.
- `Modules/User` ha corruzione git indipendente (`git fsck`: missing commit
  `cb443028...`), preesistente, fuori scope, segnalata.
