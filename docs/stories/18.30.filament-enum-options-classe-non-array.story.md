# Story 18.30 — `->options()` prende la classe dell'enum

## Il fatto

`Modules/Ptv/app/Filament/Tables/Filters/WorkerTypeFilter.php` conteneva:

```php
Select::make('type')
    ->options(WorkerType::class)      // già corretto
    ->label('Tipo lavoratore')        // vietato dalla regola no-filament-labels
    ->reactive(),

private function getWorkerTypeOptions(): array   // morto, mai chiamato
{
    foreach (WorkerType::cases() as $type) { $options[$type->value] = $type->label(); }
}
```

Il file è **untracked**: mai committato, scritto nel working tree condiviso, quindi
`git` non lo attribuisce a nessuno. Segnalato dall'utente il 2026-09-08.

Lo stato trovato è una correzione **lasciata a metà**: la chiamata era già stata
portata a `->options(WorkerType::class)`, ma il metodo privato che serviva la
versione vecchia era rimasto lì, insieme a un `->label()` a mano. Due errori della
stessa famiglia nello stesso file.

## Perché è grave anche se "funziona"

`WorkerType` dichiara `implements HasColor, HasIcon, HasLabel`. Passando la classe,
Filament 5 legge tutti e tre. Ricostruendo l'array a mano si tiene la label e si
buttano icona e colore — **senza nessun errore**: il select si popola, i test
passano, nessun log. È la categoria di errore peggiore di questo repo: quella che
non ha niente che la faccia fallire.

Causa reale, non "disattenzione": costruire un array di options è il **riflesso
generico di PHP**, e vince sull'API specifica del framework ogni volta che la
conoscenza non è nel second brain. La forma corretta era già usata **36 volte** nel
repo, e c'era pure il componente `UI\EnumSelect`: il precedente esisteva, non è
stato cercato.

## Fatto

- [x] `WorkerTypeFilter`: rimosso il metodo privato morto, rimosso `->label()`,
      aggiunto il commento sul perché la classe passa icona e colore. `php -l` ok.
- [x] Guardia `Modules/Xot/tests/Unit/Filament/EnumOptionsArePassedAsClassTest.php`,
      2 test verdi, PHPStan 0:
      1. nessuna classe sotto `Filament/` ha un metodo `*Options()` che itera `::cases()`
         (esclusione dichiarata per nome: `UI\EnumSelect`, dove la generazione sta di proposito);
      2. i `->options(Enum::options())` residui sono in una **lista dichiarata**: convertirne
         uno vuol dire toglierlo dalla lista, aggiungerne uno fa diventare il test rosso.
- [x] Regola `docs/wiki/rules/filament-enum-options.md` + bridge in `bashscripts/ai/.agents/rules/`
- [x] Memoria `errore-che-funziona-non-si-vede` (tipo `feedback`)

## Da fare

- [ ] **Notify, 1 residuo dichiarato**: `SendWhatsAppPage.php:86` fa
      `->options(WhatsAppDriverEnum::options())`. `WhatsAppDriverEnum` **non**
      implementa `HasLabel` (riga 15: `enum WhatsAppDriverEnum: string`, nessun
      `implements`), quindi passare la classe oggi darebbe i nomi dei case al posto
      delle label — la conversione richiede prima di completare l'enum.
      Stessa situazione per `MediaTypeEnum` e `TelegramDriverEnum`, che hanno
      `options()`/`labels()` statici consumati solo dai test.
      Lavoro: `implements HasLabel` + `getLabel()` sui 3 enum, poi
      `->options(WhatsAppDriverEnum::class)`, poi togliere la riga da `$known`
      nella guardia. Gli helper statici possono restare per i chiamanti non-Filament.
- [ ] **Verificare se `UI\EnumSelect` serve ancora** (11 usi): nasce per dare icone
      e HTML alle opzioni, ma parte di quello che fa Filament 5 lo fa già nativo
      passando la classe. Se il delta è solo `allowHtml`, il componente si assottiglia.
      Non toccarlo in questa story: prima misurare i suoi 11 consumer.
