## Problema

`phpstan analyse Modules` (full run, 2026-09-06 ~21:00) riportava 4759 file_errors.
2024 di questi (esclusi i 2735 falsi positivi Pest `method.internalClass`, gia'
documentati/noti) erano concentrati in modo sospetto in `staticMethod.notFound` su
`Model::factory()` + cascata `method.nonObject`/`property.nonObject`, distribuiti su
quasi tutti i moduli (Timber 846, User 156, Catalog 93, MetalWork 88, Platform 82,
Quotation 75, WhatsApp 67, WorkOrder 62, ...).

## Root cause

`Modules/Xot/app/Models/Traits/HasXotFactory.php`, usato da `XotBaseModel` (quindi da
quasi ogni model del monorepo), aveva perso il metodo pubblico statico `factory()`.

Storia del file (stesso giorno, 2026-09-06):
1. `4f1d90ee` — aggiunto `factory(): Factory` con `@return Factory<static>` (corretto)
2. `76b27cea` — indebolito il PHPDoc di ritorno a `Factory` semplice "per PHPStan L10"
3. `c81bf340` — **rimosso l'intero metodo `factory()`**, lasciando solo `newFactory()`

Effetto: ogni chiamata `SomeModel::factory()->create()`/`createOne()` nei test/seeder
falliva sia a livello di analisi statica sia (probabilmente) a runtime.

## Fix

Ripristinato il metodo nella forma corretta (identica al commit `4f1d90ee`):

```php
/**
 * @return Factory<static>
 */
public static function factory(): Factory
{
    return static::newFactory();
}
```

File lockato (`bashscripts/lock/lock.sh`) prima della modifica, sbloccato dopo commit+push.

## Verifica

- `phpstan analyse Modules/Xot/app/Models/Traits/HasXotFactory.php` → `[OK] No errors`
- `phpstan analyse Modules/Timber` prima/dopo: **1210 → 374 file_errors totali**
  (846 → 10 errori reali non-Pest; i restanti 364 sono il noto falso positivo
  `method.internalClass` di Pest, invariato)

## Impatto stimato su altri moduli

Non ancora riverificato modulo per modulo in questa story, ma lo stesso pattern
(`staticMethod.notFound` su `factory()`) e' presente nelle baseline di User, Catalog,
MetalWork, Platform, Quotation, WhatsApp, WorkOrder, Wts, Signage — ci si aspetta un
crollo simile. **Azione per chi riprende questi moduli**: ri-scansionare DOPO questo
fix, non fidarsi delle baseline raccolte prima delle 21:08 UTC del 2026-09-06.
