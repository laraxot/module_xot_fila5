## Context

**Trigger**: Richiesta di aggiungere reordering a RatingResource (ratings list) nel modulo Rating.

**Discovery**: 7 modelli hanno `order_column` nel dominio, ma **nessuno usa `->reorderable()` in Filament Tables** (solo 1 uso in Form su Device).

**Opportunità**: Creare un pattern riutilizzabile su `HasXotTable` per evitare duplicazione.

## Architecture Constraint

**`XotBaseResource` does NOT use `HasXotTable` directly.** It delegates `table()` to `XotBaseResourceTable::configure()`, which uses `HasXotTable`. Concrete resources extending `XotBaseResource` must NOT add `use HasXotTable`.

## Discovery

### Modelli con `order_column`

```bash
grep -r "order_column" Modules --include="*.php" | grep "@property\|protected"
```

Risultato: **7 modelli** hanno il campo.

### Uso attuale di reordering

- DeviceResource/DeviceForm.php: `->reorderable()` (Form, non Table)
- Nessun uso in Filament **Tables**
- Opportunità: tutti e 7 potrebbero beneficiare del pattern

## Solution proposta (architettura)

### Paletto 1: UNICO metodo getOrderColumn() su HasXotTable

Aggiungere al trait **un solo** metodo:

```php
/**
 * Get the column used for ordering/reordering.
 * Returns 'order_column' if it exists in the model's table, null otherwise.
 * Override in subclass to use a different column name.
 */
protected function getOrderColumn(): ?string
{
    $model = $this->getModel();
    $schema = $model->getConnection()->getSchemaBuilder();

    return $schema->hasColumn($model->getTable(), 'order_column')
        ? 'order_column'
        : null;
}
```

**Design decision**:
- **No `setOrderColumn()`** — unnecessary state and lifecycle
- **No `protected ?string $orderColumn = null`** — trait is stateless
- `getOrderColumn()` checks if `order_column` exists → returns `'order_column'`, else `null`
- Subclasses that need a different column simply **override** `getOrderColumn()`

### Paletto 2: Auto-apply reordering in table()

Nel metodo `table()` di HasXotTable:

```php
public function table(Table $table): Table
{
    $table = $this->resolveTable($table);

    // Auto-reorder se order_column esiste
    $orderColumn = $this->getOrderColumn();
    if ($orderColumn) {
        $table->reorderable($orderColumn);
    }

    return $table;
}
```

**NOTA**: Non definire helper `hasOrderableColumn()` - usa direttamente `\Schema::hasColumn()` in `getOrderColumn()` per evitare duplicazione. `hasColumn()` esiste già in `XotBaseMigration` ma non in `HasXotTable`.

### Paletto 3: Convenzione di default

Se il model ha un campo `order_column`, **la tabella lo abilita automaticamente** senza dichiarazione esplicita (discovery pattern).

Override per tabelle che usano colonne diverse:

```php
// In RatingResource
class RatingResource extends XotBaseResource
{
    protected function getOrderColumn(): ?string
    {
        return 'rating_order'; // Override ONLY this method
    }
}
```

**NOT**: `public function orderColumn(): string` — breaks getter convention and has no return type hint consistent with the trait.

## Redundanza analizzata

### Prima della soluzione
- 7 modelli hanno `order_column`
- 0 usano reordering in Filament Tables
- Ogni resource che lo vuole aggiungere deve:
  1. Ricordare di aggiungere `->reorderable('order_column')`
  2. Verificare che il campo esista
  3. Fare la stessa cosa 7+ volte

### Dopo la soluzione
- **DRY**: un solo metodo `getOrderColumn()` nel trait, nessun duplicato
- **KISS**: auto-discovery di `order_column` by default, nessun setter, nessuna proprietà
- **Stateless**: nessun lifecycle da gestire, nessun rischio di stato inconsistente
- **Reusable**: qualsiasi classe che necessita una colonna diversa overridea `getOrderColumn()`
- **Zero boilerplate**: una risorsa con `order_column` lo ha automaticamente

## Ridondanza non affrontata (future improvement)

### Modello con `sortable()` trait

Alcuni modelli potrebbero usare `Spatie\Eloquent\Sortable\Sortable`:
- Fornisce `getHighestOrderColumnValue()`, `setHighestOrderColumnValue()`
- Potrebbero essere integrati overrideando `getOrderColumn()`

**Decision**: Skip per ora, scoprire se usato durante implementazione (story 5.93).
