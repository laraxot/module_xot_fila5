# XOT-17.16 — Always-On Git Collision Detection & Prevention

## GitHub (tracciamento)

| Artefatto | URL |
|---|---|
| Issue | https://github.com/laraxot/base_techplanner_fila5/issues/54 |

## User story

Come **maintainer del monorepo TecnicialPlanner**,  
voglio **gli scanner di collisioni git eseguiti automaticamente in pre-push e in CI/CD**,  
così che **nessun marker di conflitto committato raggiunga la storia dei commit**.

## Contesto (Analysis, 2026-09-03)

Dopo la risoluzione XOT-5.52 (2.209 file sporchi), emerge la necessità di rendere la
detezione **always-on**, non evento manuale. Il second brain (`docs/wiki/`) deve contenere
un playbook di emergenza pronto all'uso.

- Lo script `bashscripts/git/conflict-marker-census.py` esiste ma è **event-driven**:
  richiede esecuzione manuale o CI ad-hoc.
- I marker di conflitto erano stati **comportati** perché il dev non ha visto l'errore subito:
  `php -l` mostrava il file, ma gli errori erano in sezioni non eseguite (stub, commenti, ecc).
- Il second brain ha regole ma manca **un workflow standardizzato** per la risoluzione
  immediata al primo conflitto.
- Il `00-TRIGGER_MAP.md` (linea 182) mappa già `git collision → QMD search`, ma l'indice QMD
  deve essere stato creato con `qmd embed` affinché la ricerca funzioni.

## Obiettivi

1. **Git hook pre-push + pre-commit** → blocca push/commit se markers presenti
2. **CI gate** → step separato "collision scan" nel workflow
3. **Second brain** → playbook `git-merge-marker-sweep.md` con protocollo Always-On
4. **Rules On-Demand** → trigger map entry + QMD ricerca verificata
5. **Skill on-demand** → script QMD per ricerca rapida in wiki

## Strategia di implementazione

### Parte 1: Git hook strategy (monorepo + submodules)

Per un monorepo con submodules, **usa `core.hooksPath`** — questo rende il hook
efficace sia nella repo radice che in tutti i sottomoduli.

1. **Crea la directory** `.githooks/` alla root del monorepo
2. **Crea il hook** `.githooks/pre-push` e `.githooks/pre-commit` (eseguibili)
3. **Configura** `git config core.hooksPath .githooks` (una tantum, o nello script setup)

```bash
# .githooks/pre-push
#!/bin/bash
# pre-push: block if collision markers present in staging or working directory
bashscripts/git/check-git-collision-markers.sh
exit $?

# .githooks/pre-commit
#!/bin/bash
# pre-commit: block if collision markers in working directory
bashscripts/git/check-git-collision-markers.sh staged
exit $?
```

### Parte 2: Submodule hook strategy (from `git-merge-marker-sweep.md` §Submodule)

Ogni modulo può essere repo Git separato. Sweep **per submodule** prima del parent:

```bash
for d in laravel/Modules/*/; do
  n=$(python3 bashscripts/git/conflict-marker-census.py "$d" --orphans 2>/dev/null | tail -1)
  [ "$n" -gt 0 ] && echo "$(basename "$d"): $n file orfani/marcatori"
done
```

Il hook radice `.githooks/pre-push` deve anche eseguire questo sweep sui submodules
prima di autorizzare il push.

### Parte 3: Check script (fence-aware, da `conflict-marker-census.py`)

Lo script esistente `bashscripts/git/conflict-marker-census.py` legge i file con
`errors='surrogateescape'` e conta i marker **fuori dai fence markdown**. Lo script di check:

```bash
#!/bin/bash
# check-git-collision-markers.sh
# Usage: $0 [staged|working|both]
#   - staged: checks git diff --cached
#   - working: checks working directory vs HEAD
#   - both: checks both (default)

MODE="${1:-both}"
ROOT="laravel/Modules laravel/Themes"

if [ "$MODE" = "staged" ] || [ "$MODE" = "both" ]; then
  echo "=== Checking STAGED files ==="
  staged_files=$(git diff --name-only --cached)
  if [ -n "$staged_files" ]; then
    python3 bashscripts/git/conflict-marker-census.py $staged_files 2>/dev/null
    if [ $? -eq 0 ]; then
      echo "[OK] Nessun marcatore di conflitto in staging"
    else
      echo "[FAIL] Marcatori di conflitto trovati in staging"
      exit 1
    fi
  fi
fi

if [ "$MODE" = "working" ] || [ "$MODE" = "both" ]; then
  echo "=== Checking WORKING DIRECTORY ==="
  working_files=$(git diff --name-only)
  if [ -n "$working_files" ]; then
    python3 bashscripts/git/conflict-marker-census.py $working_files 2>/dev/null
    if [ $? -eq 0 ]; then
      echo "[OK] Nessun marcatore di conflitto in working directory"
    else
      echo "[FAIL] Marcatori di conflitto trovati in working directory"
      exit 1
    fi
  fi
fi

echo "[OK] Nessun marcatore di conflitto rilevato"
exit 0
```

### Parte 4: CI gate

Aggiungere step a `.github/workflows/ci.yml`:

```yaml
- name: Scan for collision markers
  run: |
    python3 bashscripts/git/conflict-marker-census.py laravel/Modules laravel/Themes
    if [ $? -ne 0 ]; then
      echo "::error ::Collision markers found — aborting push"
      exit 1
    fi
```

## Technical Notes

- Hook `core.hooksPath .githooks` copre sia repo radice che tutti i submodules
- Lo script census usa `errors='surrogateescape'` per gestire file binari senza crash
- I marker **dentro** i fence ``` sono esempi didattici, non conflitti — il census lo gestisce
- I puntatori LFS (`version https://git-lfs.github.com/spec/v1`) non sono marker di conflitto
- ma vanno controllati separatamente: `git grep -l 'version https://git-lfs.github.com/spec' HEAD`
- Il hook deve essere `chmod +x` e **non deve essere disabilitabile** da `git push --no-verify`

## Additional Notes

Questo story chiude il ciclo di sistema: non solo ha risolto il problema, ma lo ha
**prevenuto**. È un lavoro di qualità di processo, non di bug fixing.

Le policy da rispettare (dal `00-TRIGGER_MAP.md`):
- **Prima di editare qualsiasi file** → `bashbashscripts/lock/check.sh <path>` (lock protocol)
- **File modificato (sempre, anche 1 riga)** → `php -l` → `phpstan analyse Modules` (max level) → `phpmd.sh` → `phpinsights.sh`
- **No mixed types** → `docs/wiki/rules/no-mixed-types-pattern.md`
- **Git solo avanti** → `docs/wiki/concepts/git-forward-only-study-old-version.md`
- **QMD embed** → eseguire una volta dopo aver caricato nuove regole wiki
