## User story

Come **maintainer del monorepo**,
voglio **`phpstan analyse` a zero errori su tutto il repo, con root cause reali corrette
(non ignorate)**,
così che **il gate di qualita' torni verde senza mascherare bug o test rotti**.

## Contesto

La story `18.56` (2026-09-15) aveva chiuso lo stato a zero errori. Tra il
15 e il 21 settembre nuovi test/modifiche in 4 file, in 4 moduli diversi,
hanno reintrodotto 23 errori — nessuno riconducibile a `.neon` o a
`extension-installer` (verificato: le include commentate in `phpstan.neon`
sono corrette, gia' auto-registrate da `phpstan/extension-installer`;
testato temporaneamente riattivandole → warning "included multiple times",
ripristinato subito il file originale via `diff`, zero modifiche residue —
vedi second-brain `phpstan-extension-installer-collision.md`).

## Misura iniziale (ground truth)

```bash
cd laravel && ./vendor/bin/phpstan clear-result-cache
./vendor/bin/phpstan analyse --no-progress --error-format=json > out.json 2> err.log
```

23 errori, 4 file:

| File | Modulo | Errori |
|---|---|---|
| `Modules/Cms/tests/Feature/Auth/LoginTest.php` | Cms | 1 |
| `Modules/Quaeris/app/Listeners/UpdateContactInviteCountersListener.php` | Quaeris | 1 |
| `Modules/Quaeris/tests/Feature/Actions/SendInviteActionFailedJobRetryTest.php` | Quaeris | 4 |
| `Modules/User/tests/Feature/AuthComponentsTest.php` | User | 17 |

Nessun sintomo di mute-gate (nessun "incomplete because of severe errors"
in stderr, exit code coerente col conteggio, `totals.file_errors`
verificato — non solo la somma per-file — per lo stesso motivo di
`phpstan-json-zero-va-confermato.md`).

## Root cause per file (mai un `@phpstan-ignore` d'evasione)

1. **`AuthComponentsTest.php`** (17 errori, il grosso del totale): mancava
   `use Illuminate\Support\Facades\View;`. Le chiamate `View::exists()`/
   `View::make()` risolvevano contro una classe globale `View` inesistente
   → cascata di `class.notFound` + `argument.templateType` (Pest `expect()`
   non riusciva a risolvere il tipo generico a valle). Fix: un solo import.

2. **`LoginTest.php`** — quarta occorrenza indipendente del bug
   "`instanceof`/`@var` contro `Modules\User\Models\User` (sorella) invece
   di `BaseUser` (antenato comune reale)". Dettagli, storia delle 3
   occorrenze precedenti e nota sul pattern strutturale:
   [[user-profile-volt-instanceof-wrong-user-class]] (aggiornamento
   2026-09-21 in coda al file).

3. **`UpdateContactInviteCountersListener.php`** — `RecordNotification::
   getRecord()` risultava assente: regressione/desync rispetto al fix gia'
   documentato in
   [[quaeris-manual-invite-tracking-broken-after-migration]]. Riapplicato
   identico (il metodo, col suo docblock esplicativo, non un fix nuovo).
   Bug reale a runtime, non solo test: senza `getRecord()` i contatori
   `mail_count`/`sms_count` restano rotti in silenzio ad ogni invio.

4. **`SendInviteActionFailedJobRetryTest.php`** — 4 errori di narrowing
   (`getKey()` mixed invece di `->id` tipizzato int; `stdClass|null` da
   `DB::table()->first()` letto senza `assert()`). Nessuna modifica di
   logica/asserzioni. Dettagli:
   [[quaeris-bulk-invite-job-resilience]] (aggiornamento 2026-09-21).

## AC

- AC1: nessun `@phpstan-ignore`/`@var` override aggiunto per zittire un
  errore — ogni fix e' un narrowing reale o un import mancante.
- AC2: `phpstan.neon` non toccato (verificato `diff` contro l'originale
  dopo il test dell'ipotesi merge-damage, poi scartata).
- AC3: run finale repo-wide, cache pulita, 0 errori — vedi sotto.
