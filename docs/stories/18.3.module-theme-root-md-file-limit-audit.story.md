## Regola (perche')

Richiesta utente (2026-09-07): la root di ogni modulo/tema deve avere **al massimo 6
file `.md`**. Regola gia' stabilita in una consolidazione precedente (second-brain
`project_module_doc_consolidation_audit.md`, 2026-09-05: "Xot 129→6 files,
UI/Cms/Notify/Gdpr standardizzati a 6-file max, overflow in
docs/{features,config,examples,archived}"). Il perche': la root di un
modulo/tema deve restare scansionabile a colpo d'occhio (README + poche pagine
canoniche tipo ARCHITECTURE/TESTING/PHILOSOPHY/CHANGELOG/CONTRIBUTING), tutto il
resto (guide dettagliate, esempi, doc storiche) va sotto `docs/` in sottocartelle
tematiche.

## Verifica (2026-09-07, MAI fidarsi senza controllare)

Conteggio `.md` in root per ogni modulo e tema, verificato direttamente (non dai
commit altrui):

```bash
for m in Modules/*/; do find "$m" -maxdepth 1 -iname "*.md" | wc -l; done
```

**Risultato: tutti i moduli e temi sono gia' a <= 6** (max osservato: 6, su
`User`, `Notify`, `Gdpr` — esattamente al limite, coerente con la consolidazione
del 2026-09-05). La maggior parte dei moduli e' a 1 file (solo README).

Un altro agente ha appena fatto un commit di massa (`143d1717`, "." — messaggio non
descrittivo, su `Modules/Xot`) che ha eliminato una grande quantita' di file `.md`
legacy dalla root di Xot (`ARCHITECTURE.md`, `CHANGELOG.md`, `LICENSE.md`,
`PHILOSOPHY.md`, `TESTING.md`, e molti file tematici come `amazon.md`,
`annotations.md`, `api-urls.md`) — verificato che Xot e' ora a 1 file in root,
conforme.

**Nessuna azione di fix necessaria** — task gia' soddisfatto su tutto l'albero.

## Nota per gli altri agenti

Se stai per iniziare questo stesso audit: e' gia' fatto, verificato in modo
indipendente il 2026-09-07. Se in futuro un modulo/tema supera 6 file `.md` in
root, sposta l'eccedenza sotto `docs/` (creare sottocartelle tematiche se non
esistono), non cancellare contenuto — solo riorganizzare.

**AGGIORNAMENTO 2026-09-07 (stesso giorno, secondo giro — la nota sopra si e'
rivelata sbagliata entro poche ore):** una verifica live ha trovato di nuovo
139 file `.md` non tracciati in root di `Modules/Xot` (`ARCHITECTURE.md`,
`CHANGELOG.md`, `CONTRIBUTING.md`, `PHILOSOPHY.md`, `TESTING.md`, 6 story-stub
`18.12`-`18.17.*.story.md`, e ~127 file tematici come `amazon.md`,
`botman.md`, `models.md`, `pest.md`, ecc.), tutti **non tracciati in git**
(`git ls-files` in root mostrava solo `README.md`, confermando che il commit
`143d1717` citato sopra aveva davvero pulito la root — questi erano ricomparsi
dopo, come file nuovi mai committati, mtime uniforme 2026-09-07 12:16, quasi
certamente prodotti in blocco da uno script di conversione txt→md non ancora
ripulito).

Verifica contenuto prima di agire: confronto `diff` di un campione ampio
(amazon, botman, xls, tree, pest, models, factory, contracts, cart-session,
certificate, code-analyse, admin-template, ecc.) e poi di tutti i 127 file
tematici contro l'omologo gia' tracciato in `docs/<nome>.md` — **127/127
risultati byte-identici o strettamente un sottoinsieme piu' povero** (i file
root erano dump grezzi di link pre-conversione, `docs/<nome>.md` e' la
versione curata con frontmatter, es. `converted_from: admin_template.txt`).
I 6 file story erano stub "ready-for-dev" di una riga, gia' superati dalla
versione "done" completa in `docs/stories/18.12...18.17.*.story.md` (stesso
nome, stesso path, gia' tracciata). `ARCHITECTURE.md`/`CHANGELOG.md`/
`CONTRIBUTING.md`/`PHILOSOPHY.md`/`TESTING.md` erano duplicati identici o
sottoinsiemi dei rispettivi `docs/*.md` gia' tracciati. Nessun file conteneva
contenuto unico assente altrove.

Trovato anche che `docs/archived/` (gia' presente, popolato il 2026-09-06 da
un run precedente non commesso) conteneva gia' 127/139 di questi file,
byte-identici — conferma indipendente che questa e' la destinazione gia'
in uso per questo tipo di cleanup (vedi anche precedente analogo su
`Modules/Media`, `docs/chat/media-module-root-txt-hygiene.md`).

Azione: i 139 file sono stati spostati (mai cancellati) in `docs/archived/`
in 5 batch da ~28, con lock-check per file (`bashscripts/lock/{check,lock,unlock}.sh`,
path relativi alla root del repo) prima di ogni batch — nessun conflitto di
lock incontrato. `docs/archived/` e' in `.gitignore` del modulo (righe 11 e
139, gia' presenti in `HEAD`, non aggiunte da questa sessione — vedi
`docs/wiki/rules/module-theme-root-cleanup.md`): e' una policy esistente e
intenzionale, i file restano presenti su disco ma fuori dal tracking git per
design. Di conseguenza questa move **non produce un diff git-tracciabile** su
`Modules/Xot` (ne' lo stage ne' un file da rimuovere sono visibili a
`git status`, dato che i file erano gia' non tracciati prima). Root risultante
verificata: **solo `README.md`** (1 file, ben sotto il limite di 6).

**Nota per chi trova di nuovo file .md in root**: il pattern di ricomparsa
(mtime identico ~12:16 su tutti i 139 file, stesso giorno) suggerisce uno
script di conversione/migrazione che gira periodicamente e riscrive la root
invece di scrivere solo in `docs/`. Se il problema si ripresenta, cercare ed
eventualmente correggere lo script sorgente invece di limitarsi a ripulire
ogni volta a valle.
