## Fix applicati

### 1. `tests/Unit/Binary/BinaryAssetsNotCrStrippedTest.php` — Safe imports (reale)

```php
// prima
private function readHead(string $path, int $length): string
{
    $handle = fopen($path, 'rb');
    Assert::assertNotFalse($handle, 'impossibile aprire '.$path);

    $head = (string) fread($handle, $length);
    fclose($handle);

    return $head;
}

// dopo
use function Safe\fclose;
use function Safe\fopen;
use function Safe\fread;
// ...
/**
 * @param  int<1, max>  $length
 */
private function readHead(string $path, int $length): string
{
    $handle = fopen($path, 'rb');

    $head = fread($handle, $length);
    fclose($handle);

    return $head;
}
```

Rimossi `Assert::assertNotFalse` (dead code: `Safe\fopen` lancia eccezione
invece di restituire `false`) e il cast `(string)` (ridondante: `Safe\fread`
restituisce `string`, non `string|false`). L'annotazione `int<1, max>` segue il
precedente di `Modules/Xot/app/Actions/ModelClass/FakeSeederAction.php`.

### 2. `tests/Unit/Binary/BinaryAssetsNotCrStrippedTest.php` — `repoRoot()` (reale, non-PHPStan, trovato dal gate Pest)

Il gate Pest obbligatorio dopo il fix (1) ha rivelato 2 test rossi non
collegati a Safe: `repoRoot()` risale l'albero da `__DIR__` e ritorna la prima
directory con `.git`. In questo repo **ogni `Modules/<Mod>` ha un `.git`
proprio, disconnesso dalla root** (pattern noto, vedi second-brain
`nested-per-module-git-repos.md`): la risalita da
`Modules/Xot/tests/Unit/Binary/` trova `.git` a `Modules/Xot/` (3 livelli),
**non** la root del monorepo (6 livelli, `base_ptvx_fila5/`). I pathspec usati
piu' sotto (`laravel/**/*.png` ecc.) presuppongono la root del monorepo:
risolvendo a `Modules/Xot/` restituiscono sempre lista vuota — scansione
vacua silenziosa, i test falliscono su `assertNotEmpty`.

```php
// prima
private function repoRoot(): string
{
    $dir = __DIR__;
    for ($i = 0; $i < 8; $i++) {
        if (is_dir($dir.'/.git')) {
            return $dir;
        }
        $dir = dirname($dir);
    }
    Assert::markTestSkipped(...);
}

// dopo
private function repoRoot(): string
{
    $dir = __DIR__;
    for ($i = 0; $i < 8; $i++) {
        if (is_dir($dir.'/.git') && is_dir($dir.'/laravel')) {
            return $dir;
        }
        $dir = dirname($dir);
    }
    Assert::markTestSkipped(...);
}
```

Fix root-cause: la root valida e' quella con **sia** `.git` **sia** `laravel/`
(la stessa condizione implicita nei pathspec del test), non la prima con `.git`
tout court. Salta correttamente il repo nested di modulo.

**Verifica**: prima del fix, 2/3 test rossi ("scansione vacua", 33 assertion
totali su tutto il file); dopo, **3/3 verdi, 184 assertion** (la scansione ora
copre davvero i binari del monorepo, non piu' un sottoinsieme vuoto).

## Pest gate

Non eseguita la suite completa (290 file test in Xot): dato il precedente
osservato su IndennitaCondizioniLavoro nello stesso swarm (2265s per ~98 test
su una macchina condivisa con altri 3 gruppi concorrenti) una run completa su
Xot avrebbe un costo sproporzionato rispetto al fix (2 soli file toccati) e
comunque non potrebbe risultare verde per la guardia Livewire pre-esistente
(vedi sopra). Eseguiti invece i gate mirati sui file coinvolti:

  11 segnalazioni stantie, nessuna modifica): **8 passed, 12 assertions**.

  scope, vedi sopra) — non e' un regressione di questo lavoro, verificato
