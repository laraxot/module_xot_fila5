## Diagnosis

1. Project has `config/data.php`, `config/spreadsheet.php`, and other package configs
2. These configs reference classes like `ValidationStrategy` and `Csv` reader
3. Corresponding Composer packages are NOT installed:
   - `spatie/laravel-data` — not in composer.show output
   - `phpoffice/phpspreadsheet` — not in composer.show output (suspected)
4. Laravel bootstrap loads all config files during Larastan bootstrap phase
5. Missing classes cause fatal bootstrap error

## Acceptance Criteria

1. Identify all config files that reference non-existent packages
2. Choose resolution strategy:
   - Option A: Install missing packages `composer install spatie/laravel-data phpoffice/phpspreadsheet ...`
   - Option B: Remove or comment config files for unused packages
   - Option C: Clean up composer.lock and `composer install --no-dev` from scratch
3. Run `composer dump-autoload -o` and validate no class-not-found errors
4. Retry `./vendor/bin/phpstan analyse Modules --level 10`
5. Verify analysis completes and produces error list (not bootstrap failure)
6. Document decision in BOOTSTRAP.md

## Dev Notes

**Decision Point:** User must choose between two philosophies:
- **Minimalism:** Remove unused package configs (cleaner, faster, smaller footprint) — suitable if Spatie LaravelData and PhpSpreadsheet are not actually used in the application
- **Completeness:** Reinstall all packages that configs reference (safer, maintains config parity) — suitable if packages may be added later or are required by modules

**Temporary Workaround:** Comment out offending config lines as done for data.php:129, then search for other missing-class references. Not scalable.

**Cannot Use:** Disabling Larastan bootstrap via PHPStan config — Larastan extension has hardcoded bootstrap file that cannot be disabled without modifying the extension itself.
