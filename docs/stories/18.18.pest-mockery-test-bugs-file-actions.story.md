# Story 18.18 — Xot: 6 Pest test falliti per bug di mock Mockery

## Understand

### Problem

`./vendor/bin/pest Modules/Xot/tests/Unit/Actions/File/{FileActionStaticsTest,FileActionsTest,GetModulePathActionTest,ViewPathActionTest}.php` produce 6 fallimenti, tutti nel **setup del mock**, non nel codice sotto test:

| Test | Errore | Riga |
|---|---|---|
| `FileActionStaticsTest::url2Path riporta un asset pubblico sul filesystem` | (fail, dettaglio in output completo) | — |
| `FileActionStaticsTest::path2Url trasforma un percorso pubblico nel suo asset` | (fail, dettaglio in output completo) | — |
| `FileActionsTest::asset path action works` | (fail, dettaglio in output completo) | — |
| `GetModulePathActionTest::it gets module path from facade correctly` | `Mockery_0_Nwidart_Modules_Laravel_LaravelFileRepository::getModulePath(): Return value must be of type string, Closure returned` | `GetModulePathActionTest.php:22` |
| `GetModulePathActionTest::it gets module path from fallback correctly` | stesso errore | `GetModulePathActionTest.php:49` |
| `ViewPathActionTest::it calculates view path correctly` | `No matching handler found for Mockery_1_Modules_Xot_Actions_File_GetViewNameSpacePathAction::execute('Xot'). Either the method was unexpected or its arguments matched no expected argument list for this method` | `ViewPathActionTest.php:34` |

### Root cause (verificato, non ipotizzato)

- `GetModulePathActionTest`: il mock di `LaravelFileRepository::getModulePath()` e' configurato con `->andReturn(fn () => ...)` (una Closure) invece di `->andReturn('/percorso/stringa')` o `->andReturnUsing(fn () => ...)`. Mockery, quando il metodo reale dichiara `: string`, non accetta una Closure come valore di ritorno diretto — va o il valore finale o `andReturnUsing()`.
- `ViewPathActionTest`: l'expectation su `GetViewNameSpacePathAction::execute()` e' configurata con un argomento che non combacia con quello passato a runtime (`'Xot'` atteso ma il codice sotto test passa qualcos'altro, o l'expectation manca di `->with(Mockery::any())`/l'argomento giusto).
- Nessuno dei tre file di produzione coinvolti (`GetModulePathAction.php`, `ViewPathAction.php`, `AssetPathAction.php`) appare come causa nello stack trace — e' debito nei test, non nel codice applicativo. Confermato isolando i 4 file e rilanciando: 6 falliti, 25 passati, nessun altro modulo toccato.

### Applicabilità

Isolato e verificato lo stesso giorno di un fix PHPStan reale su `Modules/Xot/app/Actions/{ArtisanAction.php,Actions/Artisan/ShowArtisanErrorLogAction.php}` (story 18.12/`docs/chat`): quel fix e' confermato non-regressivo, questi 6 fallimenti pre-esistevano e sono indipendenti.

## Plan

1. `FileActionStaticsTest`/`FileActionsTest` (`url2Path`, `path2Url`, `asset path action works`): leggere l'assertion fallita per intero (non solo il nome del test) — probabile dipendenza da `public_path()`/percorso filesystem specifico dell'ambiente, non ancora isolata riga per riga.
2. `GetModulePathActionTest`: sostituire `->andReturn(fn () => ...)` con `->andReturnUsing(fn () => ...)` o con il valore diretto, sulle righe 22 e 49.
3. `ViewPathActionTest`: correggere l'argomento atteso nell'expectation di `GetViewNameSpacePathAction::execute()` alla riga 34, verificando cosa il codice production passa davvero (namespace risolto, non per forza `'Xot'` letterale).
4. Rilanciare i 4 file isolati, poi l'intera suite `Modules/Xot/tests/Unit/Actions/File/`.
