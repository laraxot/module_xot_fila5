## Context

PHPStan Level 10 analysis on `Modules` reveals **58 errors** of type `missingType.iterableValue` concentrated in:
- `Modules/Xot/app/Filament/Traits/HasXotTable.php` (10 method declarations)
- Test files in `Modules/Xot/tests/` (generic closures without value types)

Error signature:
```
Method getTableHeaderActions() return type has no value type specified in iterable type array.
```

Root cause: PHP 8.3 runtime does not support generic syntax in type declarations (`array<T>`). PHPDoc `@return array<T>` is present but insufficient for L10. Solution: explicit `array<K, V>` through union types or alternative patterns.

- [ ] Run PHPStan L10 on Modules/Xot → 0 errors in app/

- [ ] Git commit + push to all remotes (Xot module)

## Technical Approach

### Phase 1: Validate PHPDoc Coverage
Confirm all methods have complete `@return array<K, V>` in existing PHPDoc (already present).

### Phase 2: Type-Safe Alternatives
Evaluate patterns for L10 compliance:
1. Keep `array` runtime type + trust PHPDoc (acceptable for Filament contracts)
2. Use union return types (e.g., `array|Collection`) if semantically valid
3. Refactor high-complexity methods to explicit class returns

**Decision: Option 1** (trust PHPDoc per Filament precedent) + add granular `@var` hints where control flow warrants.

### Phase 3: Test Coverage
- Pest tests must include type assertions for array shapes
- Coverage: increment laravel/Modules/Xot/docs/coverage.md
